## 1. Forecasting — next-month packaging kg

**Split (as generated, not changed):** months 1–24 train, 25–30 validation, 31–36 test (by target month). 40 companies are held out entirely: their train/validation-window rows (8,347) are never used, and their test-window rows are part of the final test. Rows: train 25,985 · validation 8,057 · test 10,542.

**Tuning:** validation only. **Test:** evaluated once for the shortlisted model of each family after selection. Experiments: 40 (xgboost 30, random_forest 8, linear_regression_raw 1, linear_regression_logratio 1).

**Selected:** xgboost (`xgboost`), chosen on validation MAE. Final untouched test: MAE 401.6 kg · RMSE 2,749.5 kg · R² 0.9863 · median APE 6.5 %.

- Seen companies (test window): MAE 260.4 kg, R² 0.9886 (last value: MAE 441.3 kg).
- Held-out companies (never trained on): MAE 994.5 kg, R² 0.9855 (last value: MAE 1,577.5 kg).
- Target R² ≥ 0.8: **MET**.

**Important reading of R².** Packaging kg varies over five orders of magnitude between products, so pooled R² is dominated by the largest products: the naive *last-value* forecast already scores R² ≈ 0.967 on test. R² ≥ 0.80 is therefore easy here and was **not** used to choose the model; validation MAE (kg) was. The meaningful result is the error reduction versus the last-value baseline shown above.

Features (scale-free; built by `ml/eprlens_ml/forecast_features.py`, shipped with the artifact): ratios of past months and rolling means to the latest month, last year's month-to-month shift, an industry seasonality index computed from training rows only, unit-sales growth, packaging weight per unit, target-month sin/cos, history length and a one-hot industry. Company and product IDs are **not** model inputs. The model predicts log(next kg / latest kg).

## 4. Known limitations

1. **Synthetic data.** Models partly learn the generator's own equations (monthly noise ~8 %, fixed seasonality profiles). Real business data will be noisier; expect lower accuracy.
2. **Rules are aligned with the injected anomaly catalogue.** The deterministic layer was written from the same catalogue (docs/anomaly-catalogue.md) that the generator used to inject errors, so its near-perfect precision on AN01–AN08 and AN10–AN20 is expected by construction. It demonstrates the checks work; it does not show how often such errors occur or are caught in practice.
3. **AN09 (monthly spikes) is the only type left to the ML layer by design.** Its recall is the most honest measure of the Isolation Forest here.
4. **Pooled R² is scale-dominated** (see §1). Use MAE / RMSE / percentage errors per company size for judgement.
5. **Context statistics.** Anomaly features use company/product history statistics (median monthly quantity, issuer median invoice value). In production the backend must compute them from the company's own records before calling Lambda (see ml/AWS_HANDOFF.md). Reference prices come from training companies only.
6. **A whole-dataset smoke run of the rules** was used once during development to find a CSV parsing defect (the category value "NA" being read as missing). No threshold or parameter was set from it; tolerances were chosen on validation companies.
7. **No confidence intervals** are returned by the forecast; none are statistically supported by this model.
8. Holiday/real-world calendar effects, price changes and new-product cold starts with < 2 months of history are not represented beyond what the generator encodes.
9. **AN09 is only partly detected** by the combined system (39 % of test spikes). The Isolation-Forest-only threshold catches more (71 %) but with many more false alarms; the combined threshold was chosen on validation F1 under the FPR limit. Better spike features (e.g. deviation from the product's own seasonal expectation) are the obvious next step, but were not tried after the test set had been scored, to keep the test result untouched.
10. **Anomaly Lambda package size.** scikit-learn + scipy + numpy measured ~232.4 MB installed on Windows; Linux wheels are smaller but still close to Lambda's 250 MB unzipped limit. Use a Lambda layer and strip tests/caches; an ONNX Isolation Forest (needs max_features = 1.0) would remove scikit-learn from Lambda.
11. `ml/evaluation/anomaly/f1_by_anomaly_type.png` shows **recall** per type: precision per type is undefined because a false alarm on a correct record has no anomaly type.
12. Stopping rules: forecasting stopped after 20 XGBoost trials without a >0.1 % validation-MAE gain (40 configurations in total); the anomaly search stopped after 20 Isolation-Forest configurations without validation-F1 gain (28 configurations including 3 rule-tolerance settings). Neither 100-configuration budget was exhausted.
